# PLUTO aida-monitor

Лёгкий прокси-мониторинг Windows-машин **без агентов-служб, токенов и WMI**.
Сервер (ядро PLUTO или этот модуль) работает по трём простым шагам:

1. **Пинг до агента** — машина отвечает или нет, замеряется задержка.
2. **Чтение строки AIDA64** — по адресу агента отдаётся страница RemoteSensor со
   строкой показаний (формат одинаков на всех машинах):
   ```
   CPUu 3%, CPU 42°C, RAM 25%, SSD 50°C, UseC 43%, UsedSpaceC 101GB, TX 0.8 KB/s, RX 0.4 KB/s, Uptime 01:39:45
   ```
   Значения идут сразу после имени (`CPUu`, `CPU`, …) через запятую — парсер ищет
   именно «имя → число».
3. **Пинг устройств через агента** — по заданным одиночным IP и целым диапазонам
   (`192.168.1.10-20`).

## Сборка и запуск

```bash
cd aida-monitor
go mod tidy                      # подтянет gin и создаст go.sum
go build -o aida-monitor.exe .   # или aida-monitor для Linux

./aida-monitor                   # слушает :8080
```

## Конфигурация

Список агентов читается из `agents.json` рядом с бинарником (если файла нет —
используется встроенный пример в `main.go`):

```json
[
  {
    "id": "agent1",
    "address": "http://192.168.99.21:8090",
    "devices": ["192.168.99.1", "192.168.99.10-20"]
  }
]
```

- `address` — страница AIDA64 RemoteSensor (порт по умолчанию 8090).
- `devices` — одиночные IP и/или диапазоны `a.b.c.N-M`.

## Эндпоинты

| Метод | Путь                  | Что отдаёт                                   |
|-------|-----------------------|----------------------------------------------|
| GET   | `/agents`             | список агентов                               |
| GET   | `/metrics`            | метрики **всех** агентов                     |
| GET   | `/metrics/:agent_id`  | метрики одного агента (AIDA + пинги)         |
| GET   | `/health`             | `{"ok":true,"agents":N}`                     |

Пример ответа `/metrics/agent1`:

```json
{
  "cpu_usage": 3, "cpu_temp": 42, "ram_usage": 25, "ssd_temp": 50,
  "use_c": 43, "used_space_c": 101, "tx": 0.8, "rx": 0.4,
  "uptime": "01:39:45", "is_online": true, "latency_ms": 1,
  "device_pings": [
    { "address": "192.168.99.1", "is_alive": true, "latency_ms": 2 }
  ]
}
```

## Связь с ядром PLUTO

Ядро может опрашивать этот модуль (`GET /metrics`) и складывать показания в базу,
либо логика «пинг + чтение AIDA + пинг устройств» переносится прямо в
`server/src/server.js`. Пинг использует системный `ping` (флаг `-c` на Linux,
`-n` на Windows), поэтому бинарник кроссплатформенный.
