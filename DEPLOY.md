# PLUTO — инструкция по развёртыванию (v1.6.0)

## 1. Требования

- Ubuntu 22.04+ (сервер), 1 ГБ ОЗУ, ~500 МБ диска;
- Docker Engine + плагин Compose v2;
- для агентов: Windows 10/11 или Server 2016+, Go 1.12+ (только для сборки, см. часть 3).

## 2. Установка сервера

### 2.1 Docker (если ещё не установлен)

```bash
sudo apt update
sudo apt install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo usermod -aG docker $USER    # войти в систему заново
```

### 2.2 PLUTO

```bash
git clone https://github.com/pluto-monitor/pluto.git
cd pluto
cp .env.example .env             # при желании задайте свой ADMIN_PASSWORD
docker compose up -d --build     # ОБЯЗАТЕЛЬНО --build: образ собирается из исходников
docker compose ps                # статус: core — running / healthy
```

| Что | Где |
|---|---|
| Веб-консоль + REST API | `http://<IP-сервера>:8080` |
| Шлюз агентов (WebSocket) | `ws://<IP-сервера>:8443/ws` |
| База данных | том Docker `pluto-data` → `/data/db.json` |

Первый вход: **admin** / пароль из `.env` (по умолчанию `pluto`) — сразу смените его:
*Настройки → Пользователи → admin → «Новый пароль»*.

### 2.3 Firewall

```bash
sudo ufw allow 8080/tcp    # консоль
sudo ufw allow 8443/tcp    # агенты
```

### 2.4 Если порт занят (например, Zabbix на 8080)

Порты PLUTO на хосте настраиваются через `.env` — внутри контейнера они всегда 8080/8443:

```bash
# .env
PLUTO_HTTP_PORT=8090     # консоль откроется на http://<IP>:8090
PLUTO_AGENT_PORT=8443    # шлюз агентов (меняйте, если и он занят)
```

После этого `docker compose up -d --build` и консоль будет на новом порту.
Если вместо этого хотите освободить 8080, останавливайте Zabbix из **его** каталога
(`cd /путь/к/zabbix && docker compose stop zabbix-web`) — из каталога PLUTO команда
`docker compose stop zabbix-web` не сработает, т.к. такого сервиса в PLUTO-проекте нет.

### 2.4 Домен + HTTPS (опционально)

Агентам нужен `wss://` — поставьте перед ядром Caddy (TLS от Let's Encrypt автоматически):

```caddy
pluto.example.com {
    reverse_proxy 127.0.0.1:8080
}
pluto-ws.example.com {
    reverse_proxy 127.0.0.1:8443
}
```

Тогда в команде установки агента используйте `wss://pluto-ws.example.com/ws`.

## 3. Установка агентов (Windows)

Агент больше **не нужно собирать вручную**. Ядро само раздаёт исходник и установщик, а компиляция идёт
прямо на Windows-машине встроенным компилятором `csc.exe` (.NET Framework 4.x есть в каждой Windows 10/11).
Это исключает ошибки «не является действительным приложением» и несовместимость версий Go — бинарник
всегда собирается под ту архитектуру, на которой работает.

### 3.1 Получить токен

В консоли: **Агенты → «Создать токен агента»**. Скопируйте токен.

### 3.2 Установить одной строкой

PowerShell **от имени администратора** (IP и токен подставятся автоматически, если использовать строку
из окна токена в консоли):

```powershell
iwr http://<IP-сервера>:8080/agent/install.ps1 -OutFile $env:TEMP\pluto-install.ps1; & $env:TEMP\pluto-install.ps1 -Token '<ТОКЕН>'
```

Установщик:
1. записывает сервер и токен в `C:\ProgramData\pluto\agent.conf`;
2. скачивает `PlutoAgent.cs` с ядра (`http://<IP>:8080/agent/PlutoAgent.cs`);
3. компилирует его `csc.exe` в `C:\ProgramData\pluto\pluto-agent.exe`;
4. создаёт службу Windows `pluto-agent` (автозапуск, exe **без аргументов**) и запускает её;
5. до 12 с ждёт подключения и печатает вердикт: «АГЕНТ В СЕТИ» или последние строки лога.

Служба намеренно запускает exe без аргументов: сервер и токен агент читает из `agent.conf`.
Это делает установку нечувствительной к экранированию кавычек, кодировкам PowerShell
и особенностям передачи аргументов .NET-службам — всем причинам прошлых сбоев.
Чтобы сменить сервер или токен, достаточно отредактировать `agent.conf` и перезапустить
службу (`Restart-Service pluto-agent`), переустановка не нужна.

Агент появится в консоли в течение нескольких секунд, затем — живые метрики и список локальных сетей.
Лог — `C:\ProgramData\pluto\agent.log`.

Управление службой:

```powershell
sc.exe query pluto-agent        # статус
sc.exe stop pluto-agent         # остановить
sc.exe delete pluto-agent       # удалить
```

### 3.4 Телеметрия AIDA64 (60 дней истории)

Агент умеет читать **сенсорную веб-страницу AIDA64** и собирать с неё показания. В самой
AIDA64 включите веб-сенсоры (RemoteSensor); по умолчанию страница отдаётся на
`http://127.0.0.1:8090/`.

Разбираются пункты: `CPUu` (загрузка ЦП, %), `CPU` (температура ЦП, °C), `RAM` (занято ОЗУ, %),
`SSD` (температура SSD, °C), `UseC` (занято диска C, %), `TX` (скорость загрузки адаптера),
`RX` (скорость отдачи адаптера), `Uptime` (время онлайн).

Адрес страницы задаётся в `agent.conf` (строка `aida64=...`) или в консоли
(**Агенты → карточка → «Изменить» → «AIDA64 — сенсорная веб-страница»**); после смены агент
перечитает его при следующем подключении. Данные хранятся **60 дней** с ярусным сжатием
(первые сутки — каждая точка, далее поминутно, после недели — почасово), график в консоли
открывается в карточке агента, фильтр периода — от 5 минут до 60 дней.

### 3.3 Альтернатива: собрать вручную (если нужен готовый .exe)

Если на машине нет .NET Framework или вы хотите раздать готовый бинарник:

```powershell
# на Windows (любой PowerShell), в папке с PlutoAgent.cs:
& "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\csc.exe" /nologo /target:exe /out:pluto-agent.exe `
  /reference:System.Management.dll /reference:System.ServiceProcess.dll /reference:System.Net.Http.dll PlutoAgent.cs

# запуск в консоли (для проверки):
.\pluto-agent.exe -server ws://<IP-сервера>:8443/ws -token <ТОКЕН>
```

Go-версия агента (`agent/main.go`) тоже осталась в репозитории как запасной вариант, но рекомендуемый
путь — C# через `install.ps1`.

### 3.5 Glances · журнал Bars (агент не нужен)

Для Linux-серверов (Rocky Linux и др.), где Glances запущен в веб-режиме (`glances -w`,
по умолчанию порт **61208**), агент ставить не нужно: ядро PLUTO само периодически
запрашивает веб-страницу и разбирает столбцы:

- **CPU** (+ user, system, iowait, idle, irq, nice, steal), %
- **MEM** (%, total/used/free, ГБ)
- **Rx/s**, **Tx/s** — сетевые счётчики
- **Package** — температура процессора, °C

Добавление: **Журнал телеметрии Bars → «Добавить устройство»**: *Имя*, *Адрес мониторинга*
(`http://<IP>:61208`), *Ссылка на физ. сервер* (кликабельная). Данные хранятся **30 дней**
с ярусным сжатием и почасовой автоочисткой. График в карточке устройства, период — от 5 минут
до 30 дней. Интервал опроса меняется в **Настройки → Опросы → «Glances (Bars)»**.

## 4. Зеркало-ретранслятор (выход в открытый интернет)

Схема: **основной сервер остаётся в локальной сети**, а наружу выставляется отдельный
read-only экземпляр на машине с публичным IP (любой дешёвый VPS). Основной сервер сам,
по расписанию, отправляет на него снапшот состояния (устройства, агенты, события —
**без паролей, сессий и настроек**). Зеркало ничего не опрашивает и не принимает изменений:
даже при его взломе злоумышленник увидит только витрину статусов.

### 4.1. На VPS: развернуть зеркало

```bash
# Docker — как в разделе 2.1, если ещё не установлен
git clone https://github.com/pluto-monitor/pluto.git
cd pluto
cp .env.mirror.example .env
openssl rand -hex 32          # сгенерируйте секрет и вставьте в MIRROR_SECRET=
nano .env                     # MIRROR_SECRET=<секрет>, ADMIN_PASSWORD=<свой>
docker compose -f docker-compose-mirror.yml up -d --build
```

Проверка: `curl http://localhost:8080/api/health` → `"mirror":true`.

### 4.2. Домен + HTTPS (обязательно для интернета)

```caddy
# /etc/caddy/Caddyfile — Let's Encrypt выдастся автоматически
pluto.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

```bash
sudo apt install caddy && sudo systemctl enable --now caddy
sudo ufw allow 443/tcp && sudo ufw allow 80/tcp
```

### 4.3. На основном сервере: включить отправку

1. Откройте консоль → **Настройки → Зеркало**.
2. **Адрес зеркала**: `https://pluto.example.com` (домен из 4.2).
3. **Секрет**: тот же, что в `MIRROR_SECRET` в `.env` зеркала.
4. **Интервал**: по умолчанию 60 сек (можно 300 = ваши 5 минут).
5. «Сохранить» → «Отправить сейчас» → статус должен стать «успешно».

### 4.4. Контроль

- В топбаре зеркала появится плашка **«зеркало · синхр. N сек назад»**;
- На основном сервере: Настройки → Зеркало → блок «Статус» (время и результат последней отправки);
- `curl https://pluto.example.com/api/health` → `"mirror":true`.

Любая попытка изменить что-либо на зеркале вернёт «зеркало: только чтение».

## 5. Что делать после установки

1. **Устройства** → «Добавить устройство»: тип (PING / HTTP / API / RTSP / SIP), адрес, интервал, теги.
2. **Настройки → Опросы**: интервалы по типам, таймаут, порог аварии, фактор деградации.
3. **Настройки → Теги**: создайте теги (до 10 цветов), присваивайте их устройствам.
4. **Настройки → Уведомления**: Telegram, e-mail, всплывающие окна; каждый канал и событие отдельно.
5. **Пользователи**: создайте наблюдателей и отметьте, какие типы устройств им видны.

Проверки на сервере — настоящие: ICMP через системный `ping`, HTTP/API через запросы,
RTSP — `OPTIONS`/ответ `RTSP/1.0 200`, SIP — `OPTIONS`/`SIP/2.0 200` по UDP.

## 6. Проверка, что всё актуально

```bash
# Жив ли API и какая версия ядра (должно быть 1.6.0):
curl -s http://localhost:8080/api/health

# Настоящий ping изнутри ядра — ровно так оно проверяет устройства:
docker compose exec core ping -c 1 <IP-устройства>

# Живой журнал проверок:
docker compose logs -f core
```

В браузере индикатор в шапке: зелёный **«ядро: сервер · v1.6.0»** — проверки настоящие;
жёлтый **«ядро: эмуляция»** — образ устарел, пересоберите:

```bash
git pull && docker compose up -d --build
```

## 7. Эксплуатация

```bash
# Обновление из репозитория
git pull && docker compose up -d --build

# Логи
docker compose logs -f core

# Бэкап базы (база — один файл в томе)
docker compose exec core cp /data/db.json /data/db.backup.json

# Полное удаление (включая данные!)
docker compose down -v
```

Данные живут в томе `pluto-data` и переживают `docker compose down` (без `-v`),
перезагрузку хоста и пересборку образа.

## 8. Диагностика

| Симптом | Проверить |
|---|---|
| Консоль показывает «ядро: эмуляция» | Образ устарел: `git pull && docker compose up -d --build`, затем Ctrl+Shift+R |
| `curl /api/health` вернул 401 | Запущен старый образ (до 1.6) — пересоберите с `--build` |
| Консоль не открывается | `docker compose ps`, `sudo ufw status`, порт 8080 не занят |
| Агент «не подключается» | Токен скопирован полностью; `Test-NetConnection <IP> -Port 8443`; для `wss://` нужен TLS-прокси |
| Нет температур | WMI `MSAcpi_ThermalZoneTemperature` требует прав администратора и поддерживается не всеми платами |
| Забыт пароль admin | Удалите `/data/db.json` в томе и перезапустите контейнер — база создастся заново |
| Зеркало «не синхронизируется» | Секреты на обеих сторонах должны совпадать; адрес — с `https://`; на зеркале `docker compose logs core` покажет «неверный секрет» или «зеркало не настроено» |
